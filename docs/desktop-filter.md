# Управление системным фильтром из Flutter

Основной интерфейс теперь управляет **собственным** macOS System Extension через
`org.vpnguard/backend`. Отдельная лаборатория для этого режима не нужна.
Windows backend пока отсутствует; общий Flutter UI остаётся кроссплатформенным.

## Что делает тест Antigravity

Кнопка «Включить тестовую блокировку» сохраняет конфигурацию Network Extension
с режимом `block-antigravity-v1`. Расширение запрещает новые TCP/UDP socket flows
Antigravity независимо от IPv4/IPv6 и наличия VPN. `guard-probe` также остаётся
заблокированным для регрессии тестового стенда. Это **не kill switch** и не режим
«разрешать только через VPN». IP и страна не используются для разрешения трафика.

Team ID берётся из подписи работающего процесса (`kSecCSSigningInformation`) и
учитывается только после проверки требованием `anchor apple generic and
certificate leaf[subject.OU] = "<Team ID>"`. До версии расширения 5 Team ID
запрашивался без этого флага, всегда был пустым, и правило Antigravity не срабатывало.

Проверяются audit tokens ответственного приложения и владельца сокета. Для главного
процесса и четырёх helpers требуются точные signing identifiers и Team ID Google.
Для отдельного `language_server` требуется ещё совпадение CDHash с проверенным
исполняемым файлом установленной Antigravity. Обновление приложения требует повторной
проверки и нового включения режима. Имена процессов, общий префикс `com.google` и
произвольные `node`/`language_server` не являются основанием блокировки.

Не подтверждены: уже открытые соединения, все запускаемые сторонние инструменты,
DNS через системный resolver, переживание сбоев и отсутствие утечек при смене маршрута.
Неопределённая идентичность разрешается с записью о неполном покрытии; UI не показывает
полноценную защиту. Ограничения прежнего лабораторного фильтра остаются применимы.

## Сборка

Обычный `flutter build macos --debug` сохраняет возможность собрать интерфейс без
платной команды. Он содержит адаптер, но не права установки/включения фильтра.
UI объясняет необходимость подписанной сборки; отсутствие capability не трактуется
как действующая защита.

Подписанная сборка из корня репозитория, после `flutter pub get` в `apps/desktop`:

```sh
VPN_GUARD_TEAM=YOUR_TEAM_ID \
VPN_GUARD_BUNDLE_PREFIX=com.example.vpnguard.desktop \
  tools/build_desktop_macos.sh
```

Скрипт использует текущий аккаунт Xcode, Apple Development и automatic provisioning.
Оба target подписываются одной командой, получают собственные profiles и общую
App Group. Секреты и профили в Git не добавляются. Результат:
`build/desktop-signed/Build/Products/Debug/VPN Guard.app`.
Поместить его в `/Applications/VPN Guard.app`; затем запускать именно эту копию.
Не включать одновременно старый Lab-фильтр и основной фильтр.

## Ручная проверка

1. С выключенной блокировкой проверить обычный доступ Antigravity к сети.
2. В основном окне нажать «Установить / обновить фильтр». Разрешить расширение
   в macOS, если система запросит. Вернуться в приложение и нажать «Проверить компонент».
3. Сохранить работу Antigravity, включить тестовую блокировку и перезапустить
   Antigravity, чтобы проверить **новые** соединения.
4. Сопоставить ошибку подключения в Antigravity с `Dropping Antigravity flow`
   в журнале фильтра. Одного отсутствия ответа недостаточно: нужны рабочий baseline
   и доступность той же сети для независимого контрольного клиента.
5. Нажать «Отключить фильтр» в основном окне. Проверить восстановление доступа.
   Выключение сохраняет `isEnabled = false` только в собственной конфигурации;
   установленное расширение остаётся в системе.

```sh
/usr/bin/log stream --style compact \
  --predicate 'subsystem == "org.vpnguard.prototype"'
```

При повторении обрыва связи отключить собственный фильтр. На предыдущем стенде
пользователь восстанавливал соединение переподключением Amnezia. Не отключать
сторонние фильтры, SIP или системную защиту для обхода ошибки.

## Контракт и границы

- `getStatus`: versioned protocol, capability, версия/состояние расширения, состояние
  сохранённой конфигурации, проверка Antigravity и её language server.
- `installFilter`: только запрос активации/обновления собственного расширения;
  не включает конфигурацию фильтра автоматически.
- `enableAntigravity`: требует установленной текущей версии и проверенных файлов.
- `disableFilter`: доступен независимо от обнаружения приложения и профиля блокировки.
- `openAntigravity`: открывает проверяемое приложение; не закрывает его и не отправляет запросов в чат.

Сохранённая включённая конфигурация **не является подтверждением** решений provider.
`protectionVerified` и `admissionGranted` остаются false. Неизвестный протокол,
повреждённый ответ и ошибки backend не преобразуются в статус «Защищено».
Разрешения и настройки Amnezia/Cisco не изменяются.

Исходники provider общие для Lab и desktop. Проекты включены в Git; поддерживающий
скрипт `tools/configure_desktop_filter.rb` повторяемо добавляет target в Runner.
Пользователю Ruby для обычной сборки не нужен.
